# Agent Note: 实时电平发布与短窗绘制

Status: implemented

## Problem

语音电平需要跟随当前声音，短促的声音也需要有可见峰值。网络操作不能让电平停在旧读数，切换声源与断线也不能保留旧的响度历史。

## Decision

- `core/audio` 以 20ms 节拍合并麦克风与远端混音的两个 0–1 响度标量。节拍允许调度抖动，延后时只发布最新值，不补发过期读数。
- `VoiceEngine::spawn` 把控制事件回调与电平回调分开。控制事件仍进入 `core/session` actor；电平回调写入最新值缓存，在订阅出口合成既有 `SessionEvent::Levels`，避免等待协议命令。所有 `Client` 调用仍由 actor 串行执行。
- actor 用 `VoiceEngine::set_meter_epoch` 按连接代次控制电平发布，订阅出口过滤旧代次；Dart 丢弃断开后的在途指标。音频设备回调与音频样本留在 Rust，FFI 仍使用单个 `CoreEvent` 流。
- RMS 映射、噪声门与快速上升、平滑回落留在 Rust。Dart 在下一帧直接绘制新指标，保留约半秒响度历史；切换声源与断开时清空历史。减少动态效果只控制装饰动画，电平仍反映实时输入。
- 电平写入独立的 `voiceLevelsProvider`，不写 `SessionView`，避免以指标刷新率重建频道树与聊天区域。

## Alternatives considered

- **在慢速指标上增加 UI 插值**：插值不能补出新声音，还会延后或压低短脉冲的可见峰值。
- **只提高刷新率，继续排入 actor**：网络命令仍会阻塞消费，旧读数也会占用控制事件队列。
- **新增专用 FFI 电平流**：固定的两个标量可复用现有事件流，额外接口与生命周期没有对应收益；多频段指标需要另行评估。
- **把原始样本送到 Dart**：可视化只需要聚合响度，跨语言传样本会破坏音频帧仅留 Rust 的约束。

## Consequences

- 50Hz 会增加 UI 事件数量；单个事件的数据固定为两个标量，界面订阅范围限定在电平画布。
- 波形表达响度历史，不表达音频逐样本波形或频谱。空闲时没有常驻呼吸动画。
- 电平可以在 actor 等待网络时更新，控制事件和协议状态仍遵守原有串行顺序。

## Testing

- `core/audio` 的电平测试覆盖节拍、调度抖动、不补发旧读数与快速上升；引擎测试在控制事件队列无人消费时接收电平，不启动真实音频设备。
- `VoiceActivityRibbon` 的像素测试覆盖新峰值在第一帧可见、减少动态效果、切换声源和断开复位；`SessionController` 测试覆盖快照不受电平影响，以及断开后丢弃在途指标。
