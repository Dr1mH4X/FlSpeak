# Agent Note: 右上角瞬时提示

Status: implemented

## Problem

页面级错误原先分散在连接页的 `NoticeBar`、工作区外壳的横幅、工作区语音区的第二条横幅，以及设置页的底部 `SnackBar`。它们占据内容流，出现时把服务器列表、频道内容或语音区推开；身份提升这种进度信息也被当成错误显示；同一错误在添加服务器对话框里还可能同时出现在字段和全局横幅中。

## Decision

页面级瞬时错误与提示收敛到 `lib/core/notices.dart` 的 `NoticeCenter`，由 `lib/widgets/notice_host.dart` 在 `MaterialApp.router` 的 builder 顶层 `Stack` 右上角渲染。

- `AppNotice` 带 tone（error / info）、自增 id；`NoticeCenter` 负责去重、最多保留 3 条，并让同文案同 tone 的重复提示刷新计时。
- 浮层绝对定位，不参与页面布局；错误 8 秒、提示 5 秒后自动消失，鼠标悬停或键盘聚焦时暂停，关闭按钮随时可用。
- `SessionView` 删除 `notice` 与 `voiceNotice`，只保留 `failureSeq` 供连接页判断失败；会话错误、语音错误、身份提升进度都直接推入 `NoticeCenter`。
- 表单校验（添加服务器、身份昵称、快捷键录制）留在输入框或模态内；设备不可用 chip 与身份提升横幅保留为持久状态。
- 连接页的等待状态由 `connect()` 的返回值和 `failureSeq` 变化释放，不再依赖提示文案。

## Alternatives considered

**继续使用内联横条**。实现最省事，但正是要解决的布局位移来源；连接页、工作区外壳、语音区各有一套，位置与计时无法统一，因此否决。

**使用底部 `SnackBar`**。Flutter 自带，但桌面端离视线远，且一次只能显示一条，连续错误会排队等待，无法同时呈现多条提示，因此否决。

**每个页面各自做浮层**。可以保留页面级样式自由，但会重复实现定位、计时、关闭与无障碍，且切换页面时提示会消失，因此否决。

**用对话框报错**。可读性最强，但打断当前操作，关闭后又需要重新找回上下文，不适合连接超时这类高频瞬时错误，因此否决。

## Consequences

- 错误与页面内容分离，服务器列表、频道内容与语音区不再因提示出现而位移。
- 提示会自动消失，离开屏幕的用户可能错过；连接状态、设备 chip、身份提升横幅这些持久信号继续留在页面上。
- 宿主位于 `Navigator` 之上，提示会盖在打开的对话框上；表单错误不进入队列，因此不会出现字段与右上角各一份的重复。
- 队列上限 3 条，错误密集时最早的瞬时提示会被丢弃；被丢弃的只是提示，核心状态仍在页面与 `SessionView` 中。
