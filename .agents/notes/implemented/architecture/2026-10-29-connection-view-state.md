# Agent Note: 连接目标与界面状态的归属

Status: implemented

## Problem

单个核心句柄只维持一个服务器连接。切换服务器时提前替换界面中的档案 id，会让协议仍连接 A 时界面已经显示 B；断开事件、连接 API 回复与连接事件又通过不同异步路径到达。普通操作失败和连接失败共用提示事件，也不能据此推断频道快照失效。

## Decision

SessionController 保存待连接档案，新连接先重置当前句柄，再发起连接；已经连上同一个档案时直接返回。activeServerId 随有序 State 事件切换：断开时清空，Connecting 或 Connected 时采用待连接档案。重置完成前的旧连接事件不能采用待连接档案，首次连接失败后的自动重连仍沿用请求目标。API 失败结束页面等待；连接页面在断开阶段保留自己的待连接目标，支持连接事件先于或晚于 API 回复。

连接状态控制频道、成员、消息与说话指示的生命周期。Disconnected 清理当前连接，Reconnecting 保留目标档案并清除无效快照和电平；普通 Failed 事件在仍然连接时只显示提示。忙碌状态由进行中操作计数持有，断开事件不会提前结束其他命令。

启动时主动拉取的服务器列表仅在没有更新的 Servers 事件时应用。频道加入操作在请求密码或回滚选择前核对原服务器、连接代次和 provider 生命周期。

具体交互回调的目标隔离与热键生命周期见[异步交互的目标与状态归属](../../implemented/architecture/2026-10-29-ui-async-ownership.md)。

## Alternatives considered

**点击服务器就乐观替换当前档案**。协议核心可能拒绝第二个连接，界面身份与实际协议目标会分离；待连接目标与当前连接必须分开持有。

**等待 connect API 回复后才处理当前档案**。广播事件可能已经到达，无法依靠两条异步路径之间的到达顺序推断服务器。界面使用 State 事件的内部顺序。

**收到任何 Failed 就清空列表**。历史文件或档案操作失败不代表协议连接失效，清空会让仍然在线的会话失去频道与成员。

**只按界面的 connected 决定是否断开**。核心可能已经开始界面尚未收到的重连任务，显式重置才能取消该任务并串行进入新目标。

## Consequences

服务器切换需要等待旧连接断开，期间新的服务器选择入口停用。断开失败会结束切换，界面不会把仍然在线的服务器改名；新连接失败则显示核心实际报告的断开状态。

状态单测覆盖断开失败、替代连接失败、重复选择当前服务器、过期初始列表、重置前事件、首次失败后的自动重连和重连电平；组件测试覆盖 API 回复与 Connected 事件的两种顺序，以及跨连接和销毁后的密码请求。
