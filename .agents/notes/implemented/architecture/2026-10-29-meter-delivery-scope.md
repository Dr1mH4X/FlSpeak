# Agent Note: 电平缓存与连接代次

Status: implemented

## Problem

50Hz 电平与状态、聊天共用有界广播时，慢订阅者会因指标占满容量而错过重要事件。断开后的旧电平回调也可能晚于新连接到达；共享麦克风值与播放包络若没有代次，会把旧声音显示在新连接上。

## Decision

协议事件保留有序广播，电平使用 watch 保存最新的 LevelReading。actor 为电平发布者设置当前连接代次，回调只更新相同代次的读数；断开和新代次清零。SessionSubscription 以订阅时的当前代次初始化，优先交付协议事件，再合并属于最近一次已交付 Connected 事件的电平。FFI 继续提供单个 CoreEvent 流，Dart 仍只收到两个响度标量。

采集与播放的 Start 命令携带连接代次。采集是带代次麦克风槽的唯一写入者，代次随原子值发布；新连接只读取新代次样本。采集停止清除麦克风槽，播放代次变化清除包络，在新流就绪前发布零值。播放流重建清除旧解码状态并保留聋听开关，避免界面仍显示聋听时恢复声音。设备回调继续只搬运样本，原子指标在工作线程处理。

电平 watch 的发送者由 actor 与音频线程持有，它们退出后 SessionSubscription 结束，核心句柄保留的协议广播发送者不会阻止 FFI 转发任务释放。释放 SessionHandle 会请求关闭 actor，防止 actor 自己持有的命令发送者延长会话生命周期。

刷新频率与绘制方式仍由[实时电平发布与短窗绘制](../../implemented/architecture/2026-10-29-realtime-voice-levels.md)规定。

## Alternatives considered

**扩大共享广播容量**。只能延后溢出，电平对慢消费者没有重放价值，保留大量旧指标还会增加延迟。

**只在 Dart 检查 connected**。重连后该值已经为真，不能分辨读数属于哪次连接。连接代次在 Rust 生产与合并阶段校验。

**只清零共享数值，不标记生产代次**。旧采集线程仍可在清零后回写，新流需要能够拒绝这次写入。

**增加独立 FFI 电平接口**。订阅出口可以合并两类数据，独立接口会增加 Dart 生命周期协调；原始音频样本也不需要进入 FFI。

**重建播放流水线时重置所有字段**。解码缓冲需要清理，聋听属于用户控制状态，需要跨设备与连接重建保留。

## Consequences

慢消费者会跳过中间电平，仍能得到最新值；协议广播自己的容量限制仍然存在，但指标不会占用它。优先协议事件可能在大量聊天时推迟一次电平更新，避免重要状态为指标让路。

测试覆盖一万次指标更新后的状态与聊天保留、重连前后旧回调、未采集新样本时的零值，以及显式关闭或释放真实句柄后的订阅结束。
