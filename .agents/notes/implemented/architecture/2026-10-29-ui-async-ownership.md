# Agent Note: 异步交互的目标与状态归属

Status: implemented

## Problem

用户可以在选择图片、上传、浏览文件或注册热键尚未结束时切换目标。回调若只检查组件仍在屏幕上，会把结果写入另一个收件人或覆盖更新的状态；并行命令结束一个就清除忙碌标志，也会提前开放操作。

## Decision

聊天草稿按投递范围和私聊客户端身份隔离。选图结果归属发起时的目标；上传结束时若目标已切换，仅把公开地址缓存回原草稿，不发送消息。服务器与连接代次切换由工作区键重建组件，草稿仅存在于内存。上传与收发规则见[TS6 图片附件与富文本](../../implemented/architecture/2026-10-18-ts6-attachments.md)。

文件列表与热键注册使用请求代次，只应用最新请求的结果。更换热键和应用销毁会松开由该组件按下的 PTT；原生注册的过期回复不能改变失焦兜底策略。macOS 窗口释放时注销 Carbon 热键并移除使用窗口指针的事件处理器。快捷键录制暂停有效绑定和 PTT；录制结束后由应用恢复最近偏好中的绑定，设置页只等待原生注销完成。

音频输入和输出选择共用顺序队列，轮到操作时基于最近成功状态合并两个设备。会话忙碌状态使用进行中操作计数，异步失败提示在 provider 销毁后停止读取本地化状态。

聊天滚动只在用户位于底部或本端发送时跟随新消息；消息数量达到保留上限时仍按最新消息变化判断。滚动意图与程序动画分开记录，富文本、图片或惰性布局修正内容尺寸时继续跟随最新位置；用户滚动取消待执行动画，避免阅读历史时被布局更新拉回底部。

## Alternatives considered

**所有回调只检查 mounted**。组件存活不代表收件人、路径或注册请求仍相同，需要同时检查操作所归属的目标或代次。

**所有操作使用最新请求覆盖**。文件列表适合该策略，输入和输出设备则是对同一状态的局部修改，直接覆盖会丢失另一侧选择，所以设备修改采用顺序合并。

**切换收件人时清空全部草稿**。这会丢失用户未发送的内容；内存隔离保留编辑上下文，应用退出时释放。

**设置页独立注销与重新注册热键**。应用层会保留过期的注册标志，并继续处理应用内按键；统一的录制状态让应用负责释放 PTT、暂停输入与恢复绑定。

## Consequences

上传期间整个输入区保持忙碌，切换目标不会自动重放发送；用户回到原草稿后可明确重试。文件列表旧请求可能继续消耗网络，但其响应不能覆盖当前界面。

组件测试覆盖延迟选图、跨目标上传、非当前草稿发送完成、封顶消息滚动、乱序文件列表和热键注册；设备与 provider 测试覆盖并行操作及销毁后的回调。
