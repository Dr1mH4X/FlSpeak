# Agent Note: 用户卡电平条与可选声源

Status: implemented

## Problem

频道栏底部的用户卡同时显示昵称与「已连接 / 未连接」，还要放麦克风、耳机、离开三个开关。它占掉了整块背景，却只在重复别处已有的身份与连接信息；语音客户端最有价值的实时信息「现在有没有声音」反而没有位置。

Material 3 没有现成的音频可视化组件。界面需要一条跟随真实电平的波形，并且让用户在设置里选择波形跟随本端麦克风还是远端接收到的音频。

## Decision

- 语音连接卡显示连接状态与当前频道；操作行把电平条放在麦克风、耳机、离开开关左侧，身份管理由主页与设置承担。
- `VoiceActivityRibbon` 使用主题 `primary` 色与圆角竖条，按响度调整高度和透明度；空闲显示短线，不做常驻呼吸动画。刷新、投递与复位策略见[实时电平发布](../architecture/2026-10-29-realtime-voice-levels.md)。
- RMS、噪声门与平滑留在 Rust；Dart 用独立电平流驱动画布，不写 `SessionView`。
- 偏好项 `voiceMeterSource` 只有 `microphone` / `received` 两档，默认麦克风；设置的「语音」分组用单选弹层切换，切换不需要重连。
- 整机系统音频回环（ScreenCaptureKit / WASAPI loopback）不实现，设置里不出现第三项。

## Alternatives considered

- **只用 `selfSpeaking` / `speaking` 布尔值**：能区分「有人在说」，但两路声源看起来一样，也无法表达音量；放弃。
- **把电平塞进 `SessionView`**：持续变化的电平字段会让频道树与聊天页一起重建；放弃。
- **新增独立 FFI 电平流**：两个固定标量可复用既有 UI 事件流；刷新与投递策略见[实时电平发布](../architecture/2026-10-29-realtime-voice-levels.md)，多频段数据需要另行评估。
- **整机系统音频回环采集**：需要平台权限、新的采集路径和三平台实现，用户已明确删除该选项。
- **M3 播放器式音频卡**：封面、进度、播放控件对应的是媒体播放，本应用没有可播放内容；放弃。
- **引入可视化库**：依赖面大于一条自绘 ribbon，且难以完全贴合现有 M3 token；放弃。
- **在 Dart 侧做 FFT**：必须先拿到音频帧，直接违反音频边界；放弃。

## Consequences

- 波形使用聚合电平，能表达有没有声音和大致响度，做不到逐帧波形或频段分析。
- 电平事件复用既有会话事件流，音频样本留在 Rust。
- 身份管理由主页与设置承担；语音连接卡显示当前连接与音频控制。
- 切换声源只改本地偏好，Rust 始终同时计算两路电平。

## Testing

- `core/audio` 覆盖 RMS、dB 映射、噪声门、平滑和刷新节拍。
- `VoiceActivityRibbon` 的像素测试覆盖首帧峰值、声源切换、减少动态效果与断开复位。平台设备时延与声源偏好在重启后保持通过 `just run` 手动检查。
- 运行机制见 [docs/audio.md](../../../../docs/audio.md)，样本隔离见[音频帧不过 FFI](../architecture/2026-10-08-audio-boundary.md)。
