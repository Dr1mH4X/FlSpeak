# Agent Note: 频道加入的回退位置由调用方指定

Status: implemented

## Problem

进入频道有两条入口：频道行的右键菜单和双击。两者都先把主区域的高亮移到目标频道，再让 core 移动自己；服务端拒绝（密码错误、权限不足、命令进行中）时高亮要退回原处，否则主区域会停在一个自己没进去的频道上。

「原处」在两条入口上不是同一个值。双击的第一次点击已经改过高亮，回退位置只能是点下去之前记下的那一个；右键菜单不动高亮，回退位置就是点菜单那一刻的选中。回退位置若由加入逻辑自己推导，得到的是目标频道本身——双击时选中已被第一次点击改成目标，回退成了空操作；退回 `null` 则交给 `activeChannelIdProvider` 的兜底规则，主区域会跳到「自己所在的频道」或「第一个根频道」，用户看到的是点了 A 失败却停在 B。

## Decision

- 两条入口共用一条加入路径，回退位置作为必填参数传入：`channel_pane` 的 `join` 接受必填的 `SelectedChannel? fallback`。
- 右键菜单传 `ref.read(selectedChannelProvider)`：菜单不预先改高亮，要退回的就是当下选中。
- 双击传 `_pendingTap.fallback`：第一次点击之前由 `ref.read(selectedChannelProvider)` 记下，第二次点击落在双击窗口内时才交给加入。
- 回滚条件在 `SelectedChannelController.join` 里：只有高亮仍停在刚请求的频道上才退回 `fallback`，期间用户换了目标就以新的为准。
- `fallback` 可以是 `null`，表示点下去之前本来没有选中，此时由 `activeChannelIdProvider` 按自己的规则挑展示频道。

## Alternatives considered

- **回退位置做成可选参数**：两个入口都能省略，漏传在编译期看不出来；失败后的高亮改由兜底规则决定，同一个操作在不同视图数据下停在不同频道。
- **在加入逻辑内部读 `selectedChannelProvider`**：双击第一次点击已把选中改成目标频道，读到的回退位置等于目标，回退不生效。
- **在加入逻辑内部读 `activeChannelIdProvider`**：它自带「自己所在的频道」与「第一个根频道」两条兜底，失败后主区域会漂到用户没点过的频道。
- **先加入、成功后再改高亮**：服务端往返期间高亮不跟随点击，单击选择与双击加入会给出两套延迟不同的反馈。
- **两个入口各写一份加入逻辑**：收起抽屉、切回工作区、回滚高亮要同步维护两份。

## Consequences

- 新增入口必须自己回答「失败后退回哪里」，函数签名挡住漏传。
- 回退位置在点下去或点菜单的那一刻取值，之后的状态变化不追认。
- 双击加入分两拍：第一次点击提交高亮，第二次点击才发移动请求。

## Testing

- `test/channel_pane_widget_test.dart` 覆盖双击被拒后退回点击前的高亮，以及右键加入被拒后退回点菜单前的选中——自己被放在另一个频道时也回到菜单前选中，而不是自己的频道。
