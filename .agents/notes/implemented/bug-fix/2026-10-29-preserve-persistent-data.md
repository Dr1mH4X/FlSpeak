# Agent Note: 保存失败时保留持久化数据

Status: implemented

## Problem

TeamSpeak 身份决定服务器上的权限，读取失败时生成新身份会破坏用户的恢复机会。档案直接截断写入、偏好并发使用同一暂存文件，以及替换失败后删除目标文件，都可能使一次普通保存损坏已有数据。

## Decision

身份只在文件不存在时生成，其他读取与解析错误原样返回。服务器档案无法读取时中止会话启动，避免把空列表当作可写状态。

Rust 的身份、服务器档案和历史压缩结果共用同目录原子写入：随机独占暂存文件、写入并同步、rename 替换，失败时保留目标并清理本次暂存文件。Unix 新文件权限为 0600。Dart 偏好按提交顺序写入，失败返回对应调用者并释放队列，后续保存可以重试。

档案增删先修改副本，保存成功后替换内存列表并发布 Servers；失败通过 SessionError::Storage 返回调用方，界面保留可重试的操作。

身份升级与线程归属仍由[双线程全双工语音](../../implemented/architecture/2026-10-18-full-duplex-audio.md)规定；本记录规定已有数据的保留语义。

## Alternatives considered

**替换失败后删除目标再重命名**。失败原因可能是权限或文件系统错误，删除会把可恢复的原文件变成丢失的数据。[Dart File.rename](https://api.dart.dev/dart-io/File/rename.html) 与 [Rust fs::rename](https://doc.rust-lang.org/std/fs/fn.rename.html) 已提供目标替换语义，失败向上传递。

**任何加载错误都使用默认值继续写入**。这适合可重建的界面偏好，不适合身份私钥与服务器档案；后者需要保留原始文件供用户恢复。

**所有 Rust 保存共用固定暂存名**。不同写入可能争用暂存文件；独占随机文件让每次操作只清理自己的数据。偏好由单个存储实例串行保存，固定暂存名足以覆盖该实例的并发调用。

**先更新内存再后台保存档案**。调用方会收到成功并继续连接，而重启后档案又恢复原状；磁盘与内存以同一次保存结果为准。

## Consequences

损坏的身份或档案需要用户修复文件后重新启动相关会话，应用不会静默替换它们。原子替换保证进程中断时目标文件完整，文件系统或硬件故障后的持久性仍取决于平台。

测试覆盖损坏身份保留、损坏档案拒绝启动、替换失败清理、并发完整文件发布、偏好最后提交值与失败后重试，以及档案操作失败时的内存和事件保留。
