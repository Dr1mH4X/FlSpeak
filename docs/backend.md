# 后端核心链路与生命周期

本文定义后端（Rust `core/`）在语音通信、状态同步、断线重连、身份升级、消息历史与文件传输等关键链路的端到端运行时契约与并发边界。

## 核心能力矩阵

| 能力 | 运行期行为 | 边界与约束 |
| --- | --- | --- |
| 语音 | `capture`/`playback` 双线程独立驱动；麦克风采集 → Opus 编码 → Actor 发送；网络接收 → 每说话人 JitterBuffer/解码/混音 → 播放；支持 mute/deafen/PTT；根据频道属性动态切换编码模式 | 不做回声消除、降噪与包重排序；音频帧绝不跨越 FFI 边界 |
| 同步 | 连接建立后拉取频道与成员快照；通过成员事件增量更新；连接存活期间每 30 秒轮询一次频道/成员/codec 状态 | 频道创建与删除依赖周期性快照轮询兜底 |
| 重连 | 意外断线后按 1/2/4/15/30/60/120/300s 阶梯退避重试；首轮连接成功前最多尝试 5 次，建立连接后不限次数 | 每次手动连接与断开递增 generation，丢弃过期延迟重试任务 |
| 身份 | 连续 3 次握手超时自动将安全等级提升 5 级（上限 29）；在独立操作系统线程运行，支持取消，原子写盘 | 仅在身份文件缺失时重新生成 |
| 历史 | 文本消息按服务器写入本地 NDJSON 文件（上限 500 条/服务器），重新建连时全量回放 | 本地明文存储，与 identity 同目录 |
| 文件传输 | 频道目录浏览、下载保存、进度通知；主机固定为通过连接检查的 SRV 会话目标 | 传输主机严格核对会话目标；普通文件上传 UI 与断点续传尚未接线 |

## 语音线程拓扑与并发

```text
session 线程（actor，独占 Client）
  │  控制命令（mute/deafen/PTT/codec/设备）
  ├──────────────┐
  ▼              ▼
capture 线程     playback 线程
cpal 输入        cpal 输出
  │                ▲
  └── Outbound ──> actor ── Client::send_voice(data, codec)
                         ← on_voice_data ── 有界通道
```

- `cpal::Stream` 必须在创建它的线程上使用和销毁。`capture` 与 `playback` 各自独占一个操作系统线程；会话 Actor 仅持有控制通道句柄，不直接访问音频设备。
- cpal 回调仅执行无锁环形队列 `ArrayQueue` 的入队与出队，保持零分配与零阻塞；格式转换、VAD、Opus 编解码与混音全部在工作线程处理。
- 所有底库 `Client` 的协议调用均在会话 Actor 中串行执行。`capture` 线程产出的 Opus 压缩包通过 `AudioEvent::Outbound` 回传给 Actor，由 Actor 串行调用 `send_voice`。
- `on_voice_data` 回调仅将压缩语音帧写入 `playback` 的有界通道；缓冲区满时直接丢弃，不阻塞协议接收循环。
- 控制通道与语音数据通道物理分离，确保静音与聋听控制指令不会被语音高频数据帧阻塞。

## 频道与成员持续同步

- 连接成功后 Actor 依次提交 `channelsubscribeall`、`channellist`、`clientlist` 与 `channellist -flags -codec`，广播 `Snapshot` 事件；订阅或标志读取失败执行优雅降级，不中断连接。
- 服务端拒绝显式列表查询时，Actor 回退使用 `tsclient-rs` 根据欢迎包与通知维护的 `directory_snapshot()`；频道顺序、主题、密码标记、人数上限与 codec 优先来自返回行，缺失时由快照补齐。
- 连接存活期间每 30 秒执行一次轮询，仅在结构内容变化时广播快照；成员变动事件保持实时增量派发，Dart 侧使用快照兜底。
- 自己的当前频道以 `ClientMoved` 事件为准，收到后查询目标频道 codec 并同步至音频子系统。
- 轮询与常规业务命令共享 Actor 串行队列，严格遵守命令限流阈值，不与建连并发。

## 断线重连与代次控制

```text
Connected ──非主动断开──> Reconnecting{attempt, delay}
    ▲                         │
    └──── 连接成功 ───────────┘
```

- 仅在非用户主动断开且此前处于连接状态的异常断线时触发自动重连。
- 退避间隔序列为 1s、2s、4s、15s、30s、60s、120s、300s；首轮会话成功前最多尝试 5 次，成功建立过会话后不限重试次数。
- 每次用户手动触发连接或断开时递增代次（generation），重连定时任务仅在代次匹配时生效，避免历史重连任务干扰新会话。
- 重连成功后重新拉取全量快照并重启语音通道；客户端保存 `lastChannelId` 并由 UI 提供快捷切回原频道操作。
- 连续 3 次建连握手超时将触发身份等级提升，升级完成后重置重连退避至 1s。

## 身份等级提升

- 连续 3 次 `wait_connected` 超时后，读取当前身份等级，计算目标等级为 `current + 5`（上限 29 级）。
- 身份挖矿在独立操作系统线程的单线程 Tokio 运行时上执行，不阻塞 Actor；支持外部通过 `AbortSignal` 取消。
- 身份、服务器档案与历史压缩结果采用同目录独占临时文件、`sync_all` 刷新与原子 rename 替换；替换失败时保留目标原文件并清理临时文件；Unix 下新文件权限严格限制为 `0600`。
- 提升进度通过 `IdentityUpgrade` 与 `IdentityUpgraded` 事件通知外部；失败时派发 `Failed` 并回退至常规重试。

## 文本消息与聊天图片

- 文本消息发送由 Actor 通过 `Client::exec_command` 提交转义后的 `sendtextmessage` 并等待服务器确认（5 秒超时）：`target_mode=1` 为私聊、`2` 为频道、`3` 为服务器广播。Dart 仅在确认成功后清空草稿。
- ServerQuery 单行存在 8192 字节上限。Actor 在发送前按 UTF-8 字符边界执行分片，优先在空白处断开。
- 戳一下交互通过 Actor 串行调用 `tsclient_rs::poke`，接收侧统一注册 `on_poked` 监听并核对连接代次转换为 UI 通知；戳一下交互不落盘写入聊天历史。
- 接收侧统一注册单一 `on_text_message` 处理器，构造 `TextMessageView` 后推入事件队列；私聊记录以发送者 UID 为持久索引键。
- TS6 协议官方图片消息使用 `{"msg_type":"ts.file.myts",...}` JSON 载荷；客户端不接入 myTeamSpeak 附件服务，官方附件统一展示格式不支持占位，不伪造图片。
- 用户自配图床与第三方 HTTP/HTTPS 图片通过 `images.rs` 进行公网 IP、SSRF 与文件头校验后安全抓取；图片裸数据不经过音频链路。

## 消息历史与文件传输

- 文本消息持久化至 `<store>/messages.jsonl`，一行一条 NDJSON 记录；启动时自动压缩保留每个服务器最近 500 条记录；写入失败派发 `Failed` 事件，不阻塞前台广播。
- 文件传输初始化（`ftinitupload` / `ftinitdownload`）在 Actor 中完成协商；数据流建立后移交独立异步 TCP 任务执行，避免大文件阻塞 Actor 命令循环。
- 文件传输主机严格限定为当前会话通过校验的 SRV 目标主机（`proto::check_transfer_host`），端口由服务端协商指定；下载过程严格校验声明字节数。
- 频道图标通过频道 0 的 `/icon_<CRC-32>` 路径下载，单图标体积限制为 1 MiB、超时 20 秒；连接代次变化时自动丢弃历史未完成结果。
