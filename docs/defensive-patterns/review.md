# 审查与调试反面准则

本文定义代码审查（Code Review）与缺陷调试（Debugging）过程中的反面模式与规范。

## 代码审查

- 错误做法：审查时泛泛而谈、提出超出审查范围的架构改造建议、对代码发表情绪化或夸奖式客套评价、放过未经验证的推测性改动。
- 正确做法：直接指出具体缺陷、给出明确且可执行的修复方案、完成关闭；结论先行，不提无关发散建议，审查前后不夸奖代码。

## 缺陷调试

- 错误做法：未读相关实现源码前根据表象推测 bug；使用试错法或在多个无关地方加 log 碰运气；原因未明时伪装成已知问题。
- 正确做法：从输入源和时序完整阅读调用链路；客观说明发现什么、在哪个具体模块/符号、如何修复，一次说清；原因不明就如实陈述现有事实，不随意猜测。
