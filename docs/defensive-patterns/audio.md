# 音频处理与线程边界反面准则

本文定义音频子系统、采集播放线程模型以及 FFI 边界的反面模式与守则。

## 音频帧绝不过 FFI

- 错误做法：通过 FFI 桥传递原始 PCM 音频帧给 Flutter 处理或绘制波形；在 UI 线程解析音频包。
- 正确做法：音频子系统由 Rust 自行采集、Opus 编解码、混音与播放。Dart 侧仅通过 `CoreEvent` 接收发言状态与事件，不传递高频音频裸帧。

## 双线程无锁环形缓冲区

- 错误做法：在音频回调中使用标准互斥锁（如 `std::sync::Mutex`）或阻塞等待；在实时音频线程中执行堆内存动态分配或 IO 操作。
- 正确做法：使用实时安全的无锁环形缓冲区传递 PCM 数据；音频采集线程与播放线程独立运作；编码后的语音包送入会话 Actor，由 Actor 串行调用 `send_voice`。
