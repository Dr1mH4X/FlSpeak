# 跨平台日志分层与职责边界

本文定义前后端结构化日志的分层边界、事实来源归属与反面模式。

## 前后端职责边界与单一事实来源

- 错误做法：前端控制器（如 `SessionController`）在 `connect()`、`disconnect()`、`joinChannel()` 等方法中记录「连接服务器」、「断开连接」、「切换频道」等日志；造成前后端日志重复记录、时序颠倒混淆。
- 正确做法：会话状态机、协议执行与网络链路的权威事实来源必须且只能是后端（Rust `core/session`）。连接阶段诊断、频道切换、协议交互与底层网络错误一律由后端权威记录并写入 `backend.YYYY-MM-DD.log`；前端是状态的消费者与展现层，严禁越权记录后端领域状态。

## 前端日志范围与合规收敛

- 错误做法：在前端各组件或交互中随意滥用 `logInfo`，或者把底层的协议事件导入前端日志流中。
- 正确做法：前端日志（`frontend.YYYY-MM-DD.log`）仅用于捕获前端自身的生命周期与表现层故障：
  - 应用启动与版本记录（`target: 'app'`，例如 `FlSpeak vX.X.X started`）
  - 本地偏好文件读写与升级失败的降级记录（`preferences`）
  - 原生系统级集成与全局快捷键注册异常（`target: 'hotkey'`）
  - 前端独占的 WebRTC 屏幕共享推流与 SDP/ICE 协商（`target: 'stream'`）

## 日志文件命名与保留期清理

- 错误做法：使用不直观的语言层命名（如 `dart.*`、`rust.*`）；前后端写入同一个文件导致并发争用与解析冲突。
- 正确做法：前端日志统一命名为 `frontend.YYYY-MM-DD.log`，后端日志统一命名为 `backend.YYYY-MM-DD.log`，均以 UTC 日期分割的 NDJSON 格式存储。保留期清理（默认保留 7 天）由前端观察器定时扫描日志目录统一执行，清理时同时兼容历史残留文件的平滑过渡。
