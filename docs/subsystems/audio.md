# 子系统契约 — core/audio

本文定义 `core/audio` 的职责、关键调用序列与不变量。

## 职责

- 管理音频输入与输出设备枚举、切换及状态监听。
- 提供双线程全双工音频处理：麦克风采集线程与扬声器播放线程。
- 封装 Opus 音频编解码器（支持 TS3 标准的 Opus Voice / Music 模式）。
- 提供语音活动检测（VAD）、输入电平测算、重采样与软削波（Soft-clipping）保护。

## 关键路径与序列

1. **输入采集链路**：
   硬件麦克风产生 PCM 数据 → 采集回调推入无锁环形缓冲区 → 采集工作线程取出 → 重采样至 48kHz 单声道 → 能量电平分析与 VAD 激活判定 → 送入 Opus 编码器压缩为语音包 → 回传给 Session Actor 调度发送。
2. **输出播放链路**：
   网络收到的 Opus 语音包交付播放引擎 → Opus 解码器解压为 48kHz PCM → 送入带固定延迟的无锁抖动缓冲（Jitter Buffer） → 混音处理与软削波平滑 → 播放回调写入声卡扬声器输出。
3. **设备重选与热插拔**：
   用户或系统切换音频设备时，平滑释放原有流并重启 cpal 硬件流，不影响底层连接会话。

## 不变量

- 原始 PCM 音频帧绝不穿越 FFI 边界进入 Flutter 进程，UI 仅感知电平与说话者状态。
- 音频实时回调线程中严禁进行锁争用、动态内存分配或系统 IO，数据交换一律使用无锁环形缓冲区。
- 无 `audio` feature 时（如基础 CI 或无媒体环境），纯数学与格式转换模块仍可独立编译并全量单测。
